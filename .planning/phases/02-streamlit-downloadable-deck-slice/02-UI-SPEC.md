## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps inside compact helper text or status rows |
| sm | 8px | Tight spacing between export button and caption |
| md | 16px | Default spacing between result preview, chart, and export controls |
| lg | 24px | Spacing before the next result section, such as SQL details |
| xl | 32px | Major vertical separation already handled by Streamlit sections |
| 2xl | 48px | Page-level breaks only; do not introduce in the export row |
| 3xl | 64px | Not used in this phase |

Exceptions: Streamlit intrinsic button height, download button padding, spinner/status spacing, dataframe spacing, and responsive column wrapping are accepted. Do not add manual CSS to override these for the PPT export.

Contract:

## Interaction Contract

### Placement

The PPT controls live inside `render_record(record, index, config)` beside the existing CSV and Excel export controls for the same result record.

Use one compact export row:

| Column | Control | Width |
|--------|---------|-------|
| 1 | `Als CSV exportieren` | `use_container_width=True` |
| 2 | `Als Excel exportieren` | `use_container_width=True` |
| 3 | `Create PPT` or `Download PPT` | `use_container_width=True` |

Rules:
- Keep the export row directly under the dataframe and chart, before `SQL-Anweisung`.
- Primary focal point is the validated result preview; secondary focal point is the PPT export action in the export row.
- Use `st.columns(3)` or equivalent equal-width columns.
- Do not add a new page, tab, modal, hero panel, decorative card, slide designer, or PowerPoint preview.
- Do not render PPTX slides, thumbnails, or slide contents in Streamlit.

### State Machine

| State | Trigger | UI |
|-------|---------|----|
| Not eligible | `can_export_presentation(record).can_export` is false | Disabled `Create PPT` plus `PPT unavailable: {reason}` caption |
| Ready to create | Eligible record, no stored deck | Active `Create PPT` button |
| Creating | User clicks `Create PPT` | `st.spinner("Creating PPT...")`; no progress bar and no page transition |
| Created | Backend returns `PresentationExport.available=True` | Replace `Create PPT` with `Download PPT`; show `PPT ready.` caption with slide count |
| Created with warnings | Export is available and `warnings` is not empty | Keep `Download PPT`; show `PPT created with warnings.` and list warnings in a compact expander |
| Failed | Backend returns `available=False` or rendering fails | Keep `Create PPT`; show `PPT export failed: {reason}. Fix the template or rerun a valid analysis, then create the deck again.` |

### Session State

Use deterministic, per-record Streamlit state:

- Initialize `st.session_state.presentation_exports` as a dict.
- Key each export by active chat and record identity: `ppt_export_{active_chat_id}_{record.get("run_id") or index}`.
- Store the backend `PresentationExport` result or an equivalent dict with `content`, `filename`, `mime_type`, `slide_count`, `warnings`, `available`, and `unavailable_reason`.
- Do not mutate `record`, `query_result`, `reporting_result`, `deck_spec`, or slide content in Streamlit.
- If `Create PPT` is clicked again after a failed or stale export, replace the stored export for that key.

### Backend Boundary

Streamlit may import only these presentation export symbols:

- `build_presentation_export`
- `can_export_presentation`
- `PPTX_MIME_TYPE`

Call contract:

- Eligibility preview uses `can_export_presentation(record)`.
- Creation uses `build_presentation_export(record=record, include_closing=False)`.
- Streamlit must not pass a custom `template_path`.
- Streamlit must not import `pptx`, `Presentation`, `SlideDeckSpec`, `SlideSpec`, `validate_template`, or any renderer internals.
- Streamlit must not inspect or mutate `PresentationExport.deck_spec`.

### Download Contract

Use `st.download_button` with:

- Label: `Download PPT`
- `data`: `PresentationExport.content`
- `file_name`: `PresentationExport.filename`
- `mime`: `PPTX_MIME_TYPE` or `PresentationExport.mime_type`
- Stable key: `download_ppt_{active_chat_id}_{record.get("run_id") or index}`
- `use_container_width=True`

The UI must use `PresentationExport.filename` exactly. Do not create a separate Streamlit filename scheme.

### Warnings And Errors

- Template warnings are non-blocking when `PresentationExport.available` is true.
- Show one visible warning line for non-empty warnings, then list warning strings in a compact expander labeled `PPT warnings`.
- Backend audit details may be shown only in an existing-style expander or caption.
- Errors are rendered with `st.error`; expected invalid states must not raise.

## Scope Boundaries

In scope:
- Add the PPT create/download control to the existing Streamlit result view.
- Preserve CSV and Excel export behavior.
- Reuse Phase 01 backend eligibility, filename, MIME type, and warnings.
- Surface short eligibility, progress, success, warning, and error states.

Out of scope:
- PPTX rendering logic in Streamlit callbacks.
- Slide order, layout, closing-slide, or chart-type controls.
- A presentation-builder page.
- PPTX preview, thumbnails, or slide inspection in the app.
- New chart support beyond backend and `visualization_spec.py` rules.
- App-wide authentication or memory RBAC UI.
