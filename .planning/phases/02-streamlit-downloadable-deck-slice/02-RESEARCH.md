### Locked Decisions

## Implementation Decisions

### Button Placement And State
- Place the PPT controls near the existing CSV and Excel export controls for a result record so users understand all exports belong to the same validated query result.
- Use a two-step stateful flow per record: `Create PPT` triggers backend generation, then a `Download PPT` control appears for the generated bytes.
- Store generated PPTX bytes and metadata in `st.session_state` keyed by a stable record/run identifier so reruns do not immediately lose the generated deck.
- Keep the UI quiet and utilitarian: no hero panel, no extra presentation-builder page, and no decorative cards around the export controls.

### Eligibility, Errors, And Warnings
- Do not show PPT export as available for records that fail Phase 1 backend eligibility. Surface a short reason near the export controls rather than letting users download broken output.
- If generation fails because the template is invalid or rendering fails, show the backend `unavailable_reason` plus warnings from `PresentationExport` in Streamlit without crashing.
- Template warnings such as known think-cell OLE entries should be visible but non-blocking when `PresentationExport.available` is true.
- Keep user-facing messages short and action-oriented; detailed audit fields can stay in expanders or captions.

### Deck Options Exposed In UI
- Phase 2 should be one-click by default and should not expose slide-order, layout, or chart-type controls.
- Do not expose `include_closing` yet. Agent 09 Closing remains opt-in in backend code and can be enabled later if there is a clear user need.
- Use whatever dynamic slide spec the backend returns. The UI should not try to inspect or mutate slide contents.
- Keep file naming from `PresentationExport.filename`; do not create a separate Streamlit naming scheme.

### Verification Strategy
- Automated tests should cover Streamlit helper behavior where possible without starting a full browser session.
- Manual Streamlit verification should confirm the visible `Create PPT` to `Download PPT` transition, filename, MIME type, warnings, and ineligible-record behavior.
- A seeded/mock successful record is acceptable for UI verification if live DB/API setup blocks repeatable checks. The record must still match the backend eligibility contract.
- Verification must confirm `streamlit_app.py` only calls the backend exporter and does not contain PPTX rendering logic.

### the agent's Discretion
- The planner may choose the exact helper names and session-state key shape as long as they are deterministic and local to `streamlit_app.py`.
- The planner may decide whether to add focused helper tests in `evaluation/test_presentation_export.py` or a new Streamlit-specific test module.

### Deferred Ideas (OUT OF SCOPE)

## Deferred Ideas

- UI controls for optional closing slide, slide presets, and visual style choices are deferred until after the basic create/download path proves useful.
- More complex chart support, top-N readability, and fallback slides stay in Phase 3.
- App-wide authentication and persistent user roles stay out of Phase 2.

### Pattern 1: Per-Record Export State Helper

**What:** Initialize `st.session_state.presentation_exports` as a dict and key entries by active chat plus record identity. [VERIFIED: 02-UI-SPEC.md; CITED: docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state]

**When to use:** Use inside `render_record` before showing PPT controls. [VERIFIED: streamlit_app.py]

**Example:**
```python
def presentation_export_key(record: dict, index: int) -> str:
    active_chat_id = st.session_state.get("active_chat_id", "chat")
    record_id = record.get("run_id") or index
    return f"ppt_export_{active_chat_id}_{record_id}"


def get_presentation_exports() -> dict:
    return st.session_state.setdefault("presentation_exports", {})
```

Source: `02-UI-SPEC.md` and Streamlit session-state docs. [VERIFIED: 02-UI-SPEC.md; CITED: docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state]

### Pattern 2: Create Once, Download Stored Bytes

**What:** Use `Create PPT` to run backend generation and save the returned `PresentationExport`; use `Download PPT` only after an available export is stored. [VERIFIED: 02-CONTEXT.md; VERIFIED: 02-UI-SPEC.md]

**When to use:** Use for successful rows/columns records in the export row. [VERIFIED: streamlit_app.py]

**Example:**
```python
eligibility = can_export_presentation(record)
export_key = presentation_export_key(record, index)
exports = get_presentation_exports()
export = exports.get(export_key)

if export and export.available:
    st.download_button(
        "Download PPT",
        data=export.content,
        file_name=export.filename,
        mime=PPTX_MIME_TYPE,
        key=f"download_{export_key}",
        use_container_width=True,
    )
elif st.button("Create PPT", disabled=not eligibility.can_export, key=f"create_{export_key}", use_container_width=True):
    with st.spinner("Creating PPT..."):
        export = build_presentation_export(record=record, include_closing=False)
    exports[export_key] = export
```

Source: Streamlit `download_button` supports `data`, `file_name`, `mime`, `key`, `disabled`, and width controls; Streamlit stores download data in memory while connected. [CITED: docs.streamlit.io/develop/api-reference/widgets/st.download_button]

### Anti-Patterns to Avoid

- **PPTX rendering in Streamlit:** Do not import `pptx`, `Presentation`, `SlideDeckSpec`, `SlideSpec`, `validate_template`, or renderer internals in `streamlit_app.py`. [VERIFIED: 02-UI-SPEC.md]
- **UI-side eligibility duplication:** Do not reimplement the Phase 1 checks for failed SQL, unsafe SQL, clarification, or missing result rows in Streamlit. [VERIFIED: src/agent/presentation_export.py; VERIFIED: 02-CONTEXT.md]
- **Index-only state keys:** Do not key PPT bytes only by `index`; the app has multiple chats and reruns, so use active chat plus `run_id` or index fallback. [VERIFIED: streamlit_app.py; VERIFIED: 02-UI-SPEC.md]
- **New deck options:** Do not expose closing-slide, layout, chart-type, slide-order, or preview controls in Phase 2. [VERIFIED: 02-CONTEXT.md; VERIFIED: 02-UI-SPEC.md]
- **New chart logic:** Do not decide in Streamlit whether a chart is exportable; use the backend result and existing `chart_spec` or `chart_plan`. [VERIFIED: src/agent/visualization_spec.py; VERIFIED: src/agent/presentation_export.py]

## Common Pitfalls

### Pitfall 1: Losing The Deck On Streamlit Rerun
**What goes wrong:** `Create PPT` returns bytes, but the next rerun hides `Download PPT`. [CITED: docs.streamlit.io/develop/concepts/design/buttons]
**Why it happens:** Streamlit reruns scripts after widget interactions, and button return values are transient unless state is stored. [CITED: docs.streamlit.io/develop/concepts/design/buttons]
**How to avoid:** Store the `PresentationExport` in `st.session_state.presentation_exports` using a stable key. [VERIFIED: 02-UI-SPEC.md; CITED: docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state]
**Warning signs:** `Download PPT` appears only during the same run that created the file. [ASSUMED]

### Pitfall 2: Duplicating Backend Eligibility In Streamlit
**What goes wrong:** UI says a deck is available while backend returns `available=False`, or the UI hides a valid backend export. [ASSUMED]
**Why it happens:** Streamlit checks `rows and columns` only, while backend also checks blocked requests, clarification, execution, validation, SQL validity, and effective row count. [VERIFIED: streamlit_app.py; VERIFIED: src/agent/presentation_export.py]
**How to avoid:** Always call `can_export_presentation(record)` for preview and `build_presentation_export(record=record, include_closing=False)` for creation. [VERIFIED: src/agent/presentation_export.py; VERIFIED: 02-UI-SPEC.md]
**Warning signs:** New UI code contains checks for `execution_success`, `sql_valid`, or `needs_clarification` outside message mapping. [VERIFIED: src/agent/presentation_export.py]

### Pitfall 3: State Key Collisions Across Chats
**What goes wrong:** A generated PPT from one chat appears under another result record. [ASSUMED]
**Why it happens:** The existing app supports multiple chats and renders records by index; index alone is not globally stable. [VERIFIED: streamlit_app.py]
**How to avoid:** Key exports with `active_chat_id` and `record.get("run_id") or index`. [VERIFIED: 02-UI-SPEC.md]
**Warning signs:** Keys such as `ppt_export_{index}` without chat or run identity. [VERIFIED: streamlit_app.py]

### Pitfall 4: Breaking VIS-01 With UI Chart Logic
**What goes wrong:** Streamlit exports a chart that the deterministic visualization contract would reject. [ASSUMED]
**Why it happens:** UI code branches on chart shape instead of consuming backend `chart_plan` / `chart_spec`. [VERIFIED: src/agent/visualization_spec.py; VERIFIED: streamlit_app.py]
**How to avoid:** Let the backend exporter use `reporting_result["chart_plan"]` or `record["chart_spec"]`; Streamlit should not inspect `deck_spec`. [VERIFIED: src/agent/presentation_export.py; VERIFIED: 02-UI-SPEC.md]
**Warning signs:** Streamlit code imports `SUPPORTED_CHART_TYPES` from the exporter or calls `build_visualization_spec` directly. [VERIFIED: 02-UI-SPEC.md]

### Pitfall 5: Planning Against The Wrong Local Runtime
**What goes wrong:** Tests fail locally before reaching Phase 2 code because the shell Python lacks project dependencies. [VERIFIED: environment probe]
**Why it happens:** Current shell Python is 3.14.5, while the project expects Python 3.11, and `streamlit` / `pptx` imports fail in the shell. [VERIFIED: environment probe; VERIFIED: Dockerfile]
**How to avoid:** Plan either a Python 3.11 virtual environment install or Docker-based validation before running PPT export tests. [VERIFIED: Dockerfile; VERIFIED: docker-compose.yml]
**Warning signs:** `ModuleNotFoundError: No module named 'pptx'` from `python -m unittest evaluation.test_presentation_export`. [VERIFIED: command output]

### Known Threat Patterns for Streamlit PPT Export

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Exporting an unsafe or failed run | Tampering | Backend eligibility blocks before rendering and UI surfaces reason. [VERIFIED: src/agent/presentation_export.py] |
| Template active content through macros or external relationships | Tampering | Existing `validate_template` blocks macros, ActiveX, unexpected embedded objects, and external relationships; known think-cell OLE entries are warnings only for approved hash. [VERIFIED: src/agent/presentation_export.py; VERIFIED: evaluation/test_presentation_export.py] |
| Wrong deck under wrong chat/run | Information disclosure | Use `ppt_export_{active_chat_id}_{record.get("run_id") or index}`. [VERIFIED: 02-UI-SPEC.md] |
| UI mutating slide content | Tampering | Streamlit imports only allowed export symbols and never inspects or mutates `deck_spec`. [VERIFIED: 02-UI-SPEC.md] |
| Sensitive secrets in errors | Information disclosure | Phase 2 should display backend unavailable reasons and warnings only; backend config errors elsewhere already sanitize connector secrets. [VERIFIED: AGENTS.md; VERIFIED: src/backends/databricks/databricks_adapter.py] |
