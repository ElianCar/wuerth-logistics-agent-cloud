<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User click to backend export | A UI action triggers backend generation from an existing record. |
| Backend export result to browser download | PPTX bytes, filename, warnings, and MIME type are rendered into Streamlit widgets. |
| Chart plan to deck export | Existing chart eligibility data moves from reporting output into the backend exporter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering | `Create PPT` action | mitigate | Use `can_export_presentation(record)` and `build_presentation_export(record=record, include_closing=False)` per D-05 and D-10. |
| T-02-04 | Information Disclosure | stored export bytes | mitigate | Store exports under `ppt_export_{active_chat_id}_{record.get("run_id") or index}` per D-03. |
| T-02-05 | Tampering | chart evidence | mitigate | Do not add Streamlit chart eligibility logic; pass the original record to the backend exporter per VIS-01 and D-11. |
| T-02-06 | Information Disclosure | error display | mitigate | Show backend reason codes and warnings only, not secrets, raw template internals, or connector values per D-06 and D-08. |
| T-02-SC | Tampering | package installs | accept | Phase 2 adds no package-manager install task; no new package legitimacy checkpoint is required. |
</threat_model>
